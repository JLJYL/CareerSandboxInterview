## 四、Disfluency removal　這條最重要，我加了合約欄位

「量到的不是使用者的口語習慣，而是 Google 的後處理」——
而且「看起來很客觀，因為有硬數字撐著」這句點出了真正的危險。
一個恆為 0 的錨點會讓流暢度對每個人給同一個分數，那比沒有這個維度更糟。

已加到 `TextStats`：

```python
filler_reliability: str = "unknown"
#   "measured"    逐字稿確實有填充詞,計數反映使用者
#   "suppressed"  引擎做了 disfluency removal,計數反映後處理
#   "unknown"     尚未由 STT_TERM_PROBE 確認
```

跟 `segmentation` 是同一種設計：讓不可信的測量值標示自己不可信，
而不是讓 prompt 去猜。

**我這側的備案已經定好，不等探測結果**：`filler_reliability != "measured"` 時，
流暢度改用不受 disfluency removal 影響的文字訊號——連接詞單調性
（然後／所以 的重複率）、句長變異、答案長度與題目複雜度的落差。
`表達流暢度` 是 `SUB_SCORE_NAMES` 的固定值域不能移除，只能換錨點。

麻煩你在 `text_stats` 填這一欄，判準由你定（我建議：計數為 0 且逐字稿
長度超過某個門檻時判 `suppressed`，但門檻你決定）。
