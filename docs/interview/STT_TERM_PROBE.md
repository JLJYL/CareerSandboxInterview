# Android STT 詞彙轉寫探測（給怡君，20 分鐘）

> 這不是「錄一段樣本」。這是量一件**構造逐字稿永遠量不到**的事：
> Android `SpeechRecognizer`（zh-TW）把技能名詞**轉寫成什麼字**。
>
> 產出有兩個用途，第二個比第一個值錢：
>   1. 讓 B 構造的黃金集逐字稿用真實轉寫形，不是想像的形
>   2. **轉寫錯的形直接補進 `skills_v1.json` 的 aliases** ——
>      這是正式環境的修復，不只是測試資料

## 為什麼非做不可

漏講判定的第一段是表面掃描：逐字稿裡出現「Angular」才算講到 `sk:angular`。
但使用者是**用嘴巴講**的，後端拿到的是 Android 轉寫的結果。若它把
Angular 轉成「安古拉」，表面掃描全滅，而使用者明明講了——系統會對著
一個講了 Angular 的人說「你漏講了 Angular」。

黃金集 10 格涉及 87 個技能詞，其中 **33 個含拉丁字母**，全部落在這個風險區。
這個數字不能猜，猜錯的方向是「測試全綠、上線全錯」。

## 做法

用**實際會出貨的那支手機**（不是模擬器——on-device 辨識的行為跟裝置、
Android 版本、Google App 版本都有關）。在 app 的語音輸入欄，
或任何呼叫 `SpeechRecognizer(languageTag="zh-TW")` 的地方，
照下面的句子唸一遍，把**原始轉寫結果**貼回來。

**不要修字。** 錯字、音譯、大小寫、多餘空格都是資料。

### 第一部分：技能詞（每句唸一次，約 12 分鐘）

用完整句子唸，不要只唸單詞——單詞辨識跟連續語音的行為不同，
而面試是連續語音。

```
1.  我主要是用 JavaScript 跟 CSS 做前端
2.  那個專案我是用 Angular 寫的
3.  後端的部分是 ASP.NET 加 C#
4.  資料庫我用的是 MS SQL
5.  版本控制我們都用 Git
6.  那時候有做 AJAX 非同步的處理
7.  jQuery 我也寫過一些
8.  切版就是 HTML 跟 CSS
9.  我熟 Excel 跟 PowerPoint，Word 也常用
10. 信箱是用 Outlook
11. 我有做過 SEO 跟 EDM 行銷
12. 用 Google Analytics 看流量
13. Canva 做圖，Instagram 跟 Facebook 都有經營
14. 公司的系統是鼎新
15. 我們用的是文中系統
16. 那時候導入 MES 製造執行系統
17. 我會 ReactJS 跟 VueJS
18. 前端跑在 IIS 上面，作業系統是 Windows 10
```

### 第二部分：中文技能詞的斷詞（約 3 分鐘）

```
19. 我每個月都要做財務報表給主管看
20. 那時候負責報表彙整還有帳務處理
21. 我做過稅務業務的部分
22. 專案時間的控管是我負責的
23. 我主要做簡報製作跟視覺設計
```

### 第三部分：填充詞會不會被吃掉（約 5 分鐘）

**這一段最重要，因為它可能推翻一整個評分維度。**

請**自然地、不流暢地**講一段兩分鐘的自我介紹。刻意多用「嗯」「那個」
「就是」「然後」，中間停頓、改口、重講。內容講什麼都可以。

然後把轉寫結果原樣貼回來。

我們要看的是：**Android 有沒有把填充詞濾掉。**

很多語音辨識引擎會做 disfluency removal，把「嗯」「那個」自動移除。
如果 Android 也這樣做，那麼 `TextStats.filler_count` 量到的不是使用者
的口語習慣，而是 Google 的後處理——它會恆為接近 0，而建立在它上面的
「流暢度」評分維度就是假的。這件事要在 B 寫 subScores prompt 之前知道。

## 回傳格式

```
【1】我主要是用 JavaScript 跟 CSS 做前端
     → （貼原始轉寫）

【2】那個專案我是用 Angular 寫的
     → （貼原始轉寫）
...

【第三部分】
     → （貼整段原始轉寫）

裝置：____________  Android 版本：______  Google App 版本：______
```

裝置資訊要填。on-device 辨識沒有單一引擎，不同機型行為可能不同——
這本身也是要知道的事。

## 拿到之後我們做什麼

| 觀察到的 | 動作 |
|---|---|
| 轉寫穩定且正確（Angular → Angular） | 表面掃描可信，照現行設計走 |
| 穩定但形式不同（SQL → Sql、Angular → 安格拉） | **補進 aliases**，正式環境即修復 |
| 不穩定（同一詞每次不同） | 表面掃描對該詞不可靠，該詞的 `kind` 判 soft |
| 填充詞被吃掉 | `filler_count` 不可當錨點，該評分維度要重新設計 |

前三種都是可處理的，最怕的是不知道是哪一種。
