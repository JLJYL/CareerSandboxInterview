# 逐字稿產生計畫（給 A、B 兩人，一次 40 分鐘做完）

> 取代原本的 `RECORDING_PLAN.md`。差別：不找組外的人、不預先寫稿。

## 核心做法：給要點，不給稿

構造與錄音不是二選一。

| 做法 | 內容可控 | 有真實 STT 特性 |
|---|---|---|
| 純手寫構造 | ✓ | ✗ 標點、術語拼寫、填充詞全是猜的 |
| 純自由錄音 | ✗ 講什麼碰運氣 | ✓ |
| **照要點口述** | **✓** | **✓** |

**照著要點自己講，不要照稿唸。** 要點決定「哪些技能會被提到、哪些刻意不提」，
所以分層精準；口述決定「怎麼被講出來」，所以停頓、改口、術語轉寫全是真的。

照稿唸會失敗，因為唸稿沒有填充詞——那正好毀掉 `filler_reliability` 的測量。
要點只寫「講什麼」，不寫「怎麼講」。

## 【已更新】探測已完成，以下是實測帶來的三個操作變更

**一、停頓超過 1–2 秒會自動送出。** 講到一半停下來想，系統就判定你講完了。
所以每段 2–3 分鐘的回答**必然要拆成數段錄**（實測者錄兩分鐘就拆了四段）。
不要對抗它——每段原樣貼進 `transcript_segments` 陣列，一段一個字串。
這反而是好事：送出邊界會變成句界，`sentence_count` 從估算值變成實測值。

**二、「嗯」「呃」講了也不會出現。** 引擎會全數移除。
所以錄音時不用刻意加它們，加了也是白加。「那個」「就是」「然後」會保留，
那些才是 `filler_count` 測得到的。T6 那段要製造不流暢感，靠這三個。

**三、英文術語會被轉錯，這是預期的，不要重錄。**
實測 `Angular→Android`、`Git→gate`、`jQuery→Jerry`、`MS SQL→msc庫`。
**轉錯的原始輸出就是我們要的資料**，改掉它等於毀掉這份測試集的意義。

## 你需要的東西：一個 APK，不是怡君的時間

跟怡君要**打包好的 app 檔**，不是請她幫忙錄。裝在自己手機上，整件事你自己做完。
這樣這件事就有 owner 了——目前它卡住的原因不是難，是三個人各持一塊。

**要不到 APK 的降級方案**：用手機內建的語音輸入（Gboard 麥克風）唸。
那不是 app 走的同一條 code path，可能不是同一個模型，所以結果要標明
`transcript_source: "stt-proxy"`。但**它仍然遠好過手寫**——Gboard 與 app 的差距，
比「真 STT」與「人寫的字」的差距小得多。不要讓完美擋住可用。

**不要為此裝 Android Studio。** 為一次 40 分鐘的取樣架幾小時的環境不划算。

## 一次做完，順序照這個

### 第一段：詞彙探測（15 分鐘）

`STT_TERM_PROBE.md` 的 23 句 ＋ 兩分鐘不流暢自我介紹。
先做這段，因為第二段要用它的結果。

自我介紹那段請刻意講「嗯」「呃」——講了但轉寫裡沒有，就直接證明引擎會濾。

### 第二段：六段逐字稿（25 分鐘）

每段 2–3 分鐘。看著下面的要點講，不要看稿。

## 六段的要點卡

三題固定：**自我介紹 → 講一個最有成就感的事 → 為什麼適合這個職位**

### T1 — Helen（資工碩二）｜用於 ivw-001／002／003

> 台大資工碩二。專題做健康紀錄 App，期末有公開展示。
> 應徵前端工程師。

**要提到**：JavaScript、Angular、Git、HTML、CSS
**刻意不提**：AJAX、ASP.NET、C#

不提的那三個是這段的重點——它們在履歷和 JD 上都有，就是要讓系統抓出
「你會但沒講」。講的時候不要提到它們，也不要說「我還會其他的」。

### T2 — Helen｜用於 ivw-004（near-perfect ＋ 唸字母）

> 同一個人，這次應徵另一個前端職缺。

**要提到**：JavaScript、Angular（履歷上的其他也盡量都帶到）
**特殊要求**：英文縮寫用**唸字母**的方式講——「H T M L」「A J A X」「C S S」

這段測 `normalize_for_scan` 的字母黏合。gap 應該接近空。

### T3 — Victor（行流大四）｜用於 ivw-005／006

> 中正行流大四。做過「在地品牌行銷企劃」課程專題，訪談 3 位消費者產出企劃書。
> 圖書館志工 60 小時、餐廳外場打工。應徵專案管理職。

**要提到**：Excel、Word
**刻意不提「專案管理」這四個字**，但**要描述你怎麼管專案**——
排時程、追進度、協調不同人、處理延遲。用「我那時候怎麼做的」講。

★ 這是整份測試集最關鍵的一段。它要驗的正是「軟技能只會被展演、
不會被指名」——如果你不小心說出「專案管理」四個字，這段就白錄了。

### T4 — Victor｜用於 ivw-007（near-zero-mention）

> 同一個人，應徵企劃職。

**要提到**：什麼技能都不要提
只講故事、講過程、講當時的感受和判斷。不要說任何工具名或能力名詞。

gap 應該接近交集全集，測天花板。

### T5 — Ken（會計大四）｜用於 ivw-008／010

> 陽交大會計大四。補習班家教帶 2 位國中生數學，每週規劃複習進度。
> 攝影社幹部，辦過 4 次社課與外拍。應徵財會助理。

**要提到**：Excel、財務報表（講「做財務報表」就好，不用講「財務報表製作」）
**刻意不提**：稅務業務

「財務報表」那句是在測詞頭匹配——詞彙表登記的是 `財務報表製作`，
你講的是 `財務報表`，看抓不抓得到。

### T6 — Ken｜用於 ivw-009（術語密集 ＋ 大量填充詞）

> 同一個人，應徵財務主管職（他其實資歷不太夠，講起來會比較虛）。

**要提到**：Excel、Outlook、PowerPoint、財務報表
**刻意不提**：帳務處理
**特殊要求**：講快、口語、想到什麼講什麼，**不要停下來修飾句子**

這段同時驗 `text_stats` 的填充詞計數與 `segmentation` 標記。
講得越亂越好——這是唯一一段「表現差」是正確答案的。

## 錄完之後

1. STT 原始輸出**一個字都不要修**，每段一個字串貼進 `case.transcript_segments`
2. `meta.transcript_source` 改 `"stt"`（或 `"stt-proxy"`），填 `meta.stt_engine`
   （裝置型號 + Android 版本 + Google App 版本）
3. 同一段逐字稿貼進它服務的所有格（T1 → ivw-001／002／003）

### 然後是標記，這步不能省

`said` 三條規則，開標前先講定：

- **指名算 2** — 原字出現：「我用 Angular 寫的」
- **展演算 2** — 具體行為描述：「我排了每週進度表，每次開會確認進度」＝專案時間控管
- **只能推論算 0** — 「我在餐廳打工過」推不出「抗壓性」

★ **要點卡上寫「要提到」不等於 `said=2`。** 你可能講了但 STT 轉錯字，
也可能以為講了其實沒講。標記要**讀逐字稿標**，不是照要點卡填。
這兩者不一致的地方，正是最有價值的資料。

前 3 份兩人各標一次，一致率低於八成回頭吵規則，不要往下標。
